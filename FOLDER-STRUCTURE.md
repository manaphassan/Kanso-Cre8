# SuamiSihat Creative Directory Hierarchy Specification

Official folder structure and naming convention standard for SuamiSihat creative design projects.

This standard establishes a searchable, chronologically indexed directory hierarchy across local workstations and network storage (`SSNAS`).

---

## Directory Hierarchy Specification

```text
Creative Workspace/                         ← WorkspaceRoot (configured in SS-CAM Settings)
│
├── _Team/                                  ← Shared team collaboration folder (v2.5.0+)
│   ├── team-notes.json                     ← Team Board notes (SS-CAM Collaboration feature)
│   └── Notes/                             ← Optional: shared Quick Notes (if NAS storage enabled)
│       ├── 0001D/
│       └── 0002S/
│
├── [Staff_ID]/                             ← Designer root folder (e.g. 0001D, 0002S)
│   ├── SS-2025/
│   └── SS-2026/                            ← Year Container
│       ├── 202601_January/                 ← Month Container (YYYYMM_Month)
│       ├── 202604_April/
│       │   ├── 202604_0070D_SS_Kegel_Voucher/
│       │   ├── 202604_0071D_SS_Rejal_Brand/
│       │   └── 202604_0072D_SSE_POSM/      ← Project Folder (YYYYMM_####X_BRAND_ProjectName)
│       │       │
│       │       ├── README.md               ← Project brief + YAML frontmatter (see spec below)
│       │       ├── Artwork Design/         ← Source files (.afdesign, .psd, .ai)
│       │       ├── Artwork Mockup/         ← Presentation mockups & client previews
│       │       ├── Assets/                 ← Raw photos, icons, reference materials
│       │       ├── Production/             ← Print & web exports (PDF, PNG, SVG)
│       │       ├── Client_Revisions/       ← [Optional] Client feedback & revision files
│       │       └── RAW_Media/             ← [Optional] Raw photo/video source files
│       │
│       └── 202607_July/
```

---

## Project Directory Naming Convention

Format:
`YYYYMM_####X_BRAND_ProjectName`

| Component | Format | Description | Example |
|---|---|---|---|
| **Date Code** | `YYYYMM` | Four-digit year + two-digit month | `202604` |
| **Job ID** | `####X` | Four-or-more digit sequence followed by the preset code: `D` Graphic/Print, `S` Social, `V` Video, `P` Brand Identity | `0072D` |
| **Sub-brand** | Identifier | Official business code (`SS`, `SSH`, `SSC`, `SSW`, `SSE`, `SST`) | `SSE` |
| **Project Name** | Title | Concise description separated by underscores | `POSM` |

### Standardized Examples
* `202604_0072D_SSE_POSM`
* `202601_0060D_SSW_Wellness_Centre`
* `202602_0069S_SSE_Flash_Sale_Thursday`
* `202602_0070D_SS_Corporate_Kegel_Voucher`

## Standard Sub-Directory Requirements

Each project directory must contain the following sub-directories:

| Sub-Directory | Required | Functional Purpose | File Types |
|---|---|---|---|
| `README.md` | ✅ Yes | Project brief, scope, frontmatter status | `.md` |
| `Artwork Design` | ✅ Yes | Working files, editable source vector and raster graphics | `.afdesign`, `.afphoto`, `.psd`, `.ai`, `.indd` |
| `Artwork Mockup` | ✅ Yes | Presentation previews, 3D renderings, and client review files | `.jpg`, `.png`, `.pdf` |
| `Assets` | ✅ Yes | Source assets, reference materials, icons, and stock graphics | Raw photos, vector icons, project fonts |
| `Production` | ✅ Yes | Exported final assets ready for print or web deployment | `.pdf` (print), `.png` (web), `.svg`, `.eps` |
| `Client_Revisions` | ⬜ Optional | Client feedback files and revision request documents | `.pdf`, `.docx`, `.jpg` |
| `RAW_Media` | ⬜ Optional | Raw photo/video files from shoots | `.dng`, `.raw`, `.arw`, `.mp4` |

## README.md Frontmatter Specification (v2.5.0+)

Every project `README.md` generated by SS-CAM v2.5.0 and later includes a YAML frontmatter block at the top of the file. This block is machine-readable and powers the **Task Manager** module.

```yaml
---
status: in-progress
designer: 0001D
client: SS
deadline: 2026-09-30
priority: medium
tags: [branding, print]
revision: 1
---

# Project Name

[Project brief content in Markdown...]
```

### Frontmatter Field Reference

| Field | Type | Allowed Values | Description |
|-------|------|----------------|-------------|
| `status` | string | `backlog`, `in-progress`, `review`, `done`, `on-hold` | Current workflow stage |
| `designer` | string | Staff ID (e.g. `0001D`) | Assigned designer |
| `client` | string | Sub-brand code (e.g. `SS`, `SSE`) | Client or business unit |
| `deadline` | date | `YYYY-MM-DD` | Target delivery date |
| `priority` | string | `low`, `medium`, `high`, `urgent` | Priority level |
| `tags` | list | Free text | Comma-separated topic tags |
| `revision` | integer | ≥ 0 | Current revision round number |

> **Backward compatibility:** SS-CAM gracefully handles `README.md` files without frontmatter — they appear in the "Untracked" column of the Task Manager.

## Shared Team Folder (`_Team/`)

The `_Team/` folder at the workspace root is a shared collaboration space accessible by all designers with NAS mount access.

| Path | Purpose |
|------|---------|
| `_Team/team-notes.json` | Team Board notes posted from SS-CAM |
| `_Team/Notes/<StaffId>/` | Optional per-designer Quick Notes (if NAS storage is enabled in Settings) |

> `_Team/` is created automatically by SS-CAM on first use of the Collaboration feature. No manual setup required.

---

## Production Guidelines

1. **Root File Exclusion**: Files must not be saved directly in the project root; all assets must be categorized into `Artwork Design`, `Artwork Mockup`, `Assets`, or `Production`.
2. **Sequential Job Numbers (`####X`)**: Maintain sequential numbering and place the preset code after the number to preserve chronological sorting across file systems.
3. **Delimiter Standard**: Use underscores (`_`) instead of spaces or special characters to maintain cross-platform compatibility across Windows, macOS, and NAS storage.
4. **README First**: Always populate the `README.md` project brief before beginning design work. The frontmatter status field is the source of truth for the Task Manager.
5. **NAS Sync**: Ensure the workspace root is within the mounted NAS drive path (configured in SS-CAM Settings → Workspace Root) so all features have full read/write access.
